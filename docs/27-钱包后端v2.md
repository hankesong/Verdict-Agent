# 钱包后端 v2

本轮完成后端和共享协议，前端页面没有修改。钱包插件发现、真实手写输入和唤起钱包仍由前端完成；服务端只做会话绑定、审查、确认校验与一次性许可消费。具体范围见 [019](decisions/019-wallet-backend-v2.md)。

## 已实现范围

| 部分 | 行为 |
| --- | --- |
| 钱包会话 | 记录账户、网络、provider ID、版本；切换账户／网络／钱包或断开会递增版本，取消未消费审查并清除旧确认 |
| 原生币 | 复用普通无代码账户转账的意图、预算、余额、nonce、费用、`eth_call`、`eth_estimateGas` 及区块一致性检查 |
| 合约调用 | 固定 ABI 的 ERC-20 `transfer(address,uint256)` 和 `approve(address,uint256)`，精确重新编码匹配 calldata，原生币 value 必须为零 |
| 合约身份 | 本地配置固定目标地址及 Keccak 运行时代码哈希；读取 EIP-1967 implementation/admin/beacon 槽，识别 EIP-1167 前缀；检测到代理或升级入口则 UNKNOWN。不能推断覆盖全部自定义代理 |
| 合约预执行 | `eth_call` 必须返回标准 true；`debug_traceCall` 不接受内部调用；`eth_simulateV1` 核对转账前后余额或 allowance，以及唯一匹配的 Transfer／Approval 日志 |
| 确认 | 客户端手写完成声明绑定本次交易、会话版本与 nonce；服务端时间、确认摘要和事件持久化；消费前缺确认即 409 |
| 消费 | 原有一次性原子消费保留，领取前复查状态；代币调用重新核对代码、代理槽、模拟及区块；复查失败清除确认 |

未知代币、未知 spender、无限授权、非零 allowance 直接改为另一个非零值、未知 selector、非标准返回、额外日志、内部调用、资产差额不符、RPC 模拟／追踪不可用，均不能得到可消费许可。模型仅复核已产生的 `policy` 和 `preflight` 依据。

## API 迁移

`GET /api/wallet/meta` 返回 `reviewSchemaVersion: wallet-review-v2` 与 `confirmationRequired: true`。只有配置启用了合约审查时，`supportedOperations` 才包含 `contract_call`。

### 1. 钱包连接后创建会话

```http
POST /api/wallet/sessions
```

```json
{"account":"0x1111111111111111111111111111111111111111","chainId":"0x3c8","providerId":"browser-wallet"}
```

返回 `sessionId`、`revision`、`connected`、时间与 `authority: CLIENT_DECLARED`。无签名、无交易，也不证明账户所有权。

收到 `accountsChanged`、`chainChanged`、`disconnect` 或选择了其他 provider 后调用：

```http
POST /api/wallet/sessions/:sessionId
```

请求包含新的 `account`、`chainId`、`providerId`、`connected` 和旧 `revision`。即使切到不支持的网络，也必须先作废旧会话版本；该版本无法再创建受支持交易之外的审查。前端仍必须在实际钱包请求前重读账户与网络。后端只能知道客户端通知的变化。

### 2. 提交明确交易与意图

```http
POST /api/wallet/reviews
```

在原 `clientRequestId`、`transaction`、`intent` 基础上，必须增加：

```json
{"schemaVersion":"wallet-review-v2","walletSessionId":"返回的会话 UUID","walletSessionRevision":1}
```

原生币 `intent.operation` 仍为 `native_transfer`。合约调用为 `contract_call`，额外提供 `functionSelector` 与 `contractAction`：

```json
{"kind":"erc20_transfer","recipient":"0x2222222222222222222222222222222222222222","amount":"100"}
```

或：

```json
{"kind":"erc20_approve","spender":"0x4444444444444444444444444444444444444444","amount":"100"}
```

合约意图的顶层 `recipient` 是交易目标代币合约；`contractAction` 中 recipient／spender 才是代币接收方或被授权方。数量是最小单位十进制整数，交易 quantity 为规范十六进制。用户意图与 calldata 独立提交并精确核对，不能只从 calldata 反向推导“用户意图”。

### 3. 审查结束后手写确认

`GET /api/wallet/reviews/:id` 返回 `confirmationNonce`。仅 `ALLOWED` 且未过期时，前端显示具体交易与结果，在本地完成本次手写后请求：

```http
POST /api/wallet/reviews/:id/confirm
```

```json
{
  "transactionDigest":"审查返回的摘要",
  "account":"0x1111111111111111111111111111111111111111",
  "chainId":"0x3c8",
  "confirmationNonce":"本次审查返回的 UUID",
  "walletSessionId":"会话 UUID",
  "walletSessionRevision":1,
  "handwritingAcknowledged":true
}
```

不接受 `name`、笔迹、图像、客户端自报时间或 verdict。声明不等于后端能够识别姓名或验证物理落笔。收到成功确认后才调用原 `/consume`（带完全相同的 preparedTransaction），随后由钱包执行真实签名。首次确认重发返回 `WALLET_ALREADY_CONFIRMED`；如响应丢失，可 GET 原审查核对 `userConfirmedAt`，不能新建确认绕过状态。

每份审查及其确认最多消费一次。取消钱包弹窗后创建新审查，不复用确认。编辑交易条件后前端调用 `/cancel`，重新审查和签写。staging 增加独立 `/override` 路径：仅当确定性检查完成且原模型给出 `PI_BLOCK` / `PI_UNCERTAIN` 时，用户可明确选择继续。硬规则失败及预执行未知仍不允许覆盖，客户端不能改写 verdict。

## 配置

合约审查默认关闭，在本地 `wallet` 配置中设置：

```json
{"contractCalls":{"enabled":true,"maxCalldataBytes":4096,"allowedSelectors":["0xa9059cbb","0x095ea7b3"]}}
```

对应 `wallet.networks[]` 的 `tokens` 中配置 `address`、`codeHash`、`maxTransferAmount`、`maxApprovalAmount`、`approvedSpenders`。`codeHash` 是已审阅运行时代码的 Keccak-256；不能从请求自报值采用，也不能在代码变化后自动更新。额度为代币最小单位。本地配置及有认证的 RPC URL 不上传。

RPC 必须支持 `eth_getStorageAt`、`debug_traceCall`（callTracer）、`eth_simulateV1`，以及原生币流程使用的方法。模拟在指定父区块之上的临时状态执行，不广播、不修改链上状态；它不保证未来执行结果。

## 验证

Node 22.23.3 / npm 10.9.9：

```sh
npm ci --ignore-scripts
npm run typecheck
npm run test:wallet
npm run test:b
npm test
```

`test:wallet` 覆盖旧请求拒绝、未确认、错误摘要／账户／链／会话／nonce、拒收额外姓名字段、重复确认、重复消费、跨任务重放、会话变化、取消竞态、过期、重启、参数变化、合约正例及多种失败／未知路径。RPC 和模型替身均明确为 TEST_TRANSPORT；图与原生币独立复验继续执行原真实内核。

v2 基础阶段已通过后端 150 项与原内核／CLI 48 项，本地真实 EVM 的两条模拟路径也通过。staging 新增风险覆盖与代币回执／复验后，后端全量 159/159 项、原内核／CLI 48/48 项通过；新增回执路径的 RPC 与模型使用 TEST_TRANSPORT，未进行公开网络交易或插件实签。旧前端 provider 的测试替身用例只作为原行为回归，不能代替 v2 的浏览器接线验证；本轮没有进行钱包插件签名测试。

可重复运行本地真实 EVM 验证（工具只安装在被忽略的 `.local`，不改变工程依赖）：

```sh
npm install --prefix .local/evm-tools --no-save --ignore-scripts @foundry-rs/anvil@1.6.0-rc1 solc@0.8.35
npm run verify:wallet:evm
```

该脚本启动独立 loopback Anvil，使用本仓库 MIT 测试合约，经 solc 编译后通过本地测试 RPC 设置初始代码和状态。当前扩展版先验证审查／许可消费不修改实际状态，再由测试驱动通过本地账户 impersonation 发送两笔交易，随后校验回执、代币状态和第二实例复验。真实 EVM 已验证 transfer：`1000,0 → 900,100`；approve：`0 → 100`；两份复验均 MATCH。后端广播次数为 0，本地测试驱动为 2；没有真实钱包私钥或公开网络交易，结束时关闭节点。模型及 harness 使用 TEST_TRANSPORT，不能作为插件实签或真实模型验证，详情见 [28](28-staging钱包查询与操作接口.md)。

## 交付边界

- 本轮无前端重做；现有钱包页面尚未适配 v2 会话与手写确认，旧创建请求会被拒绝。EIP-6963 发现和前端监听已有代码可复用，但不能据此声称插件实签已联调。
- 合约调用已增加固定配置代币的 receipt／前后状态观察与 `wallet-observation-v2` 独立复验；`receiptEvent` 和 `stateComparison` 分开保存。区块前后余额变化包含其他同期交易时，scope 标明 `BLOCK_RANGE_NOT_TRANSACTION_CAUSAL`。
- 风险覆盖接口仅在 `policy`、`preflight` 全部 PASS 且原模型 verdict 为 `PI_BLOCK`／`PI_UNCERTAIN` 时可用；硬规则拒收不允许覆盖。请求为 `POST /api/wallet/reviews/:id/override`，在确认字段之外增加 `acknowledgement: CONTINUE_WITH_RISK`。覆盖后原 status／verdict 保留，消费记录 `userOverride`，广播阶段才允许带该记录的已消费许可。
- 不支持代理代币、税币／重基代币、任意 Swap、permit、批量交易、复杂内部调用或完整漏洞审计。固定代码哈希与配置是信任前提，模拟只覆盖声明的余额／allowance 和日志。
- 没有公开网络写入，也没有用真实付费模型复测本轮新增能力。

参考：[EIP-20](https://eips.ethereum.org/EIPS/eip-20)、[EIP-1967](https://eips.ethereum.org/EIPS/eip-1967)、[Geth eth_simulateV1](https://geth.ethereum.org/docs/interacting-with-geth/rpc/ns-eth#eth_simulatev1)。
