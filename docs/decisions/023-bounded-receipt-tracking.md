# 023：staging 增加有界回执跟踪

2026-10-07。用户要求继续后端建设，沿用 [022](022-staging-backend-continuation.md) 的子分支开发、验证后回传 staging 边界。本轮复用干净的 `backend-staging-next` 工作树，从 `staging@e018db2` 继续。

工程选择：填补真实交易尚未出块时前端只能反复手动查询的缺口，增加显式启动、持久化、指数退避和有界预算的观察队列。只跟踪已经消费许可且已上报哈希的交易，复用现有回执、代币状态和证据检查。模型不参与，不新增签名、消费或广播能力。

队列采用独立表和独立版本 DTO，保持既有 review/history/actions 严格响应兼容。次数与截止时间冻结，重复请求及 resume 不重置预算。服务重启先核对已保存观察，再将未完成任务暂停，由调用方显式 resume；这不需要钱包重新签名。

跟踪完成、交易执行成功、代币效果一致和审查通过保持独立。失败回执也可完成观察，观察耗尽仍保留未知。验证、接口、恢复语义和暂未覆盖的链重组持续监测见 [29](../29-回执跟踪队列.md)。本轮不修改前端，不合入 main，不执行公开链交易。

实际验证：类型检查通过；内核／CLI 48 项、后端 183 项通过；本地真实 Anvil 的两条代币交易均从待出块自动跟踪到观察完成，并在第二实例复验 MATCH。RPC／模型替身与本地 EVM 的来源保持区分。
