# 022：围绕《周五付款》建设真实付款前端

日期：2026-10-07。状态：用户要求真实前端，并明确后端由另一工作线处理。

本记录来自钱包 v2 前端工作树。后续合入 STAGING 见 [025](025-staging-frontend-integration.md)；下文待接线内容与测试数字反映本轮开发时状态。

## 范围与分工

用户提供《周五付款》作为目标体验，要求在当前正式页面建设。此前短暂起草的 PaymentPreset 共享类型已撤回；本轮不更改 server 或 protocol，不以 UI_MOCK 剧情替代真实请求。当前接口能力核实记录见 [28](../28-friday-payment-readiness.md)，该记录反映当时工作树，不能覆盖后端后续交付。

## 前端实现

付款工作台提供新建付款、常用条件和本机付款记录。用户保存的原生币条件以账户与链隔离，本次地址或金额变更不会随之改写条件；重试先前付款也保留原 intent。预填配置明确为本机来源，不声称具有服务端可信预设的授权属性。

付款详情并排显示提交条件与实际交易：发送方、收款方、资产、金额、网络、费用与调用信息。可同时看到多项字段差异，但审批结论、确认、消费及钱包签名仍沿用后端与 GuardedWallet。拒收时未进入签名；逐次手写前另列当前金额、完整地址和网络。

异常、取消及后来重新提交的付款保留独立 review。列表从本机索引打开真实服务端记录，不预置供应商或成功付款。用户确认声明从 review 返回的时间显示；链上结果分别展示回执、状态复查、证据，不把其中一项替代其他项。

浏览器可在已支持的 BOT 原生币范围内进行有上限的回执复查，首次上报与后续复查使用不同的现有接口；最多 12 次或 2 分钟，未知不改成失败。此功能以当前页面仍打开为前提，不冒充后端持久跟踪。

## 验证与接力

类型检查、20 条钱包浏览器路径已通过；新增真实接口路径覆盖本机条件与改写草稿的独立提交、地址和金额同时突出、拒收签名、取消历史保留、正确付款重建、等待回执以及查询次数上限。RPC／模型／钱包测试传输均为隔离样本，没有真实交易。

预设服务端保存、付款批次、账单来源、付款 Agent 草稿与持久跟踪待后端接口交付后接线。前端没有制作虚假成功的账单上传或批量签名按钮，也不扩展对外防注入能力声明。
