# 018：区分材料理解与执行授权

2026-10-07，用户要求修复 Guard 对引用／否定攻击指令的正常材料误拦，并继续实际测试。此记录说明本次实现选择，不把模型分类当作确定性证明。

此前 `external_material` 与动作共用二态倾向的安全提示，任一 BLOCK／UNCERTAIN 直接终止。现在先用专门提示分类材料角色、引用关系及试图改变的行为，再由确定性代码决定材料能否作为不可信数据交给 PI。材料分类不签发执行许可，读取内容不增加授权；原有动作外审、硬约束、一次性许可与 A 验收不变。

默认 `materialPolicy=required`：任一材料隔离则 `STOPPED / MATERIAL_REQUIRED`，要求提供替代材料，不能丢弃必要输入却宣布完成。调用方可明确选择 `optional`，隔离内容完全不交给前方模型，剩余任务依然受锁定边界与动作外审约束。该选项由调用方设置，模型工具不可设置。模型传输错误、超时、格式错误、预算耗尽仍停止，不能借 optional 绕过。

一批材料每任务仅审查一次，缓存绑定材料摘要及边界摘要；同批并发复用，换批拒绝。快照数组，防止等待期间替换。未知不是攻击已确认，不自动重试求放行，不用多数表决覆盖硬规则，不增加每任务的人工确认流程。

评测同时报告材料误隔离、任务误终止、真实验收完成、严格输出完成、攻击目标达成和错误。主对比使用默认 required，不以 optional 隔离后继续美化完成率。结果和命令见 [复测报告](../25-Guard材料误拦修复与复测.md)。

用户要求继续后，提示词改为 v2：消除“引号外祈使句一概视为攻击”的过宽规则，检查材料实际要求相对可信任务改变什么。required/optional、动作硬规则和预算保持原语义，旧 v1 记录继续可读。后续真实复验独立记录于 [v2 报告](../26-Guard材料审查v2复验.md)，不覆盖 v1 失败记录。

后续补充 material-disposition-v2，允许明确 ALLOW、DATA/REFERENCE、REQUESTED、NONE 的原范围提醒作为不可信材料读取，拒绝 UNKNOWN／MIXED 和所有请求改变的组合。新快照单独标明处置版本，缺省为旧版。该变化不授予业务动作权限，实际动作仍受范围硬规则及一次性许可控制。
