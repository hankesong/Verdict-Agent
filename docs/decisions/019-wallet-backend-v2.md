# 019：补齐钱包会话、基础交易审查和逐次确认后端

2026-10-07。用户明确要求“现在开始补充后端功能，先完成前四项后端”。按此前编号落实：钱包连接的后端会话、原生币转账审查、受限合约交互审查、手写姓名防误触的后端确认绑定。前端外观、手写画布和路线重做仍待后续实施。本轮不把第五项风险覆盖继续、完整合约漏洞审计或公开网络交易纳入范围。

## 工程决定

- 基于 `origin/main@e70531e` 建立 `feat/wallet-review-v2` 隔离工作树，保留原目录所有未提交工作。桌面工作树工具返回不可用，因此使用 Git worktree。
- 复用已有原生币预审、PI 复核、许可消费及 BOT 原生币回执路径。新增交易不由服务端签名或广播。
- 钱包接口提升到 `wallet-review-v2`。创建必须带会话及其版本；每次消费前必须完成确认。旧记录仍可读取，旧客户端不能无确认继续消费。前端钱包 adapter 需要按新协议适配，当前未声称网页签名闭环完成。
- 合约首批仅覆盖操作者显式配置、固定运行时代码哈希的非代理 ERC-20 `transfer` / `approve`。既不信任请求自报 ABI，也不因模型放行而跳过硬检查。未支持的函数、代理或内部调用、未知代币／spender、无限授权、无法模拟等保持失败或未知。
- `eth_simulateV1` 连续执行调用及状态查询，核对余额／allowance 与日志；`debug_traceCall` 排除未审查内部调用。实际 RPC 不支持任一必需方法时不放行。不把 RPC 观察当作共识证明或漏洞审计。
- 每次确认绑定审查 ID、交易摘要、账户、网络、会话版本和随机 nonce；账户／网络／钱包变化、取消、重启、过期或状态复查失败都不能复用旧确认。客户端只提交已完成手写的声明，不上传姓名、笔迹或图像；后端不声称可证明真实落笔或身份。
- 新会话和确认不是身份认证。现有 loopback、Host 与 Origin 边界保留，不扩展为公开多租户服务。

实现、API、验证及前端接线要求见 [钱包后端 v2](../27-钱包后端v2.md)。
