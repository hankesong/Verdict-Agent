# 018：前端整体重做为站点式验收控制台

2026-10-08。

## 用户已确认

- 清空原有前端（旧的七个页面、样式和浏览器测试），整体重做。
- 采用讨论后定下的方案：以物流框架和动效作为记忆点，文字一律使用区块链与后端的专业术语；站点路线、工程抽屉、证据码和条码。
- 视觉参考 Claude 官网的风格：象牙白底、陶土色强调、衬线标题、细线边框。只借鉴风格，不使用其标志、字体文件或素材；品牌标识是原创图形。

## 工程选择

- 九个站点替代旧页面：01 任务登记、02 交付追踪、03 证据封存、04 独立复验、05 候选与观测、06 Agent 执行、07 动作轨迹、08 外审与报告、09 钱包审查。旧页面的能力全部保留在对应站点中。
- 动画只回放真实快照中的状态转移，并按记录顺序播放：包裹移动、核验盖章、拒收后沿虚线退回、证据条码打印。时间列来自后端记录，节奏可以压缩，但不补造耗时。
- 工程抽屉记录页面实际发出的每个请求，并按检查项的 `evidenceRefs`（JSON Pointer）在原始证据包里定位字段。抽屉只展示，不重算摘要、不验签。
- 证据码只携带 manifest 的 `schemaVersion`、`hashAlgorithm` 和 `evidenceHash`，不携带 verdict、可信上下文或查询账户。条码按摘要字节确定性绘制。
- 交付追踪中，由本页发起的运行会自动在第二实例导入并复验；通过链接或刷新打开的运行不自动写入第二实例，需要手动发起。
- 动作轨迹改为自绘 SVG，继续复用 `graph/model.ts` 的投影与归并逻辑；`graph/model.ts` 和 `wallet/provider.ts` 是有集成测试覆盖的业务逻辑，原样保留。
- 篡改挑战目前只做“修改副本后导入”这一关。“修改后重新封签”需要服务端演示接口，未实现，页面不做模拟。
