# 021：钱包优先的正式前端与基础转账审查

日期：2026-10-07。状态：用户授权开始实现，首版已落地工作树，待合入唯一上游。

以下按时间保留原工作树的实现记录；合入 STAGING 后的接线边界以 [025](025-staging-frontend-integration.md) 为准，旧记录中的后端缺项不代表当前 STAGING 能力。

## 用户确认的产品方向

- 这是唯一一版正式前端，不再制作仅用于演示的替代页面。
- 产品位于钱包或交易所操作之后，当前先做钱包连接与基础交易审查；未来再接入交易所／钱包作为中间层。
- 首页直接呈现新建转账，最近操作放在可折叠侧栏；审计工具作为辅助入口。
- 审查过程使用快递路线比喻：包裹沿真实行动节点移动，下方显示 Agent 的行动记录和状态。快递仅为视觉包装，字段和结果保持链上与后端专业术语。
- 浅色、克制的金融工具视觉；前端不撰写设计解释、开发备注、功能预告等注释性文本。
- 钱包签名前必须逐次手写姓名防误触，不做姓名识别；不自动填充、复用、上传或保存笔迹。

## 本次前端实现

- 使用 EIP-6963 发现钱包、EIP-1193 请求账户／链／交易。
- 对接主线现有钱包审查 API：提交交易意图、轮询审查、读取钱包活动图、核对 receipt、读取钱包证据和请求第二实例复验。
- 手写确认与审查许可绑定；审查许可、账户／链变化、拒签、过期和参数变化不会被前端绕过。
- 本地最近操作只保存审查索引和必要状态，不保存私钥、姓名笔迹或原始凭据。
- 保留旧账户验收、证据、服务和 Agent 工具，统一收进辅助审计入口，不让它们占据首页主流程。

## 现阶段边界

- 当前只放行后端已经支持的原生币、空 calldata 转账。代币授权、Swap、任意合约调用和合约漏洞审计仍返回不支持／未知。
- 用户要求的风险后继续执行仍需后端独立的用户选择记录与许可接口，本次没有用前端绕过 ALLOWED 许可。
- 专项浏览器测试使用隔离测试钱包、测试 RPC 和测试传输，不能写成真实插件或公共测试网交易已经完成。
- 这次修改只涉及前端以及钱包适配器为重试一致性所需的极小状态修复；没有签名、发送主网交易或部署存证合约。

## 接入钱包后端 v2

用户随后提供 `docs/27-钱包后端v2.md` 作为接线依据。本前端迁移到含 v2 后端的 `Verdict-Agent-wallet-v2` 工作树。新增服务端会话、逐次确认和失效通知；确认响应丢失读取原记录；基于固定 ABI 增加受限 ERC-20 transfer／approve 表单。覆盖范围取决于后端配置。代币回执保持未覆盖；风险后强制继续仍不可用。

此次类型检查通过，钱包相关 47 项和浏览器钱包 12 项测试通过；测试传输不等于真实钱包签名联调。原 `Verdict-Agent-frontend` 保留 v1 工作树作为先前实现，不继续作为当前预览来源。

本轮最终回归：23 条浏览器检查（原有 11 条＋钱包 12 条）、47 条钱包相关检查以及全工程 typecheck 均通过。预览 `http://127.0.0.1:5182/#wallet` 已切换到本工作树，服务端 `frontend-v2` 使用 v2 接口；当前运行配置只开放原生币，受限代币能力需配置审核过的代币与 spender 后开启。

## 快递路线改为逐步活动节点

用户进一步确认：旧 Agent 活动页暂时忽略，之后删除；本次将钱包转账进度中的快递动画改成按 Agent 行动一步一步推进，而非扩建旧活动页。

已在钱包页实现：真实钱包图事件逐条显示为步骤卡，包裹沿事件顺序移动，到站停留约 200 毫秒后继续；追加记录或画布重排时保留当前路段和运动进度，跨行沿弯曲连线移动。点击步骤打开下方对应依据，移动端纵向排列。等待签名、消费许可、钱包报告、RPC 广播核对、回执、执行后状态及证据保存保持各自状态，未记录的动作不补成完成；历史加载与减少动态效果不重播整条路线。分页与缺口恢复保留既有事件，缺失连接不绘制。本轮不改签名授权规则，不增加对旧活动页的入口，也未删除旧页面。

验证：钱包浏览器 18 条路径通过，包含到站停留、连续运动、事件完整对应、缺口补齐与移动端无横向溢出；仅使用隔离 RPC／模型／钱包测试传输。

## 本地模拟配置体验

用户要求一个假的配置入口，并确认用途为“不连接真实钱包，直接体验转账审查和快递动画”。新增本地开发的“体验流程”入口，仍复用正式钱包界面。模拟账户、0.01 tBOT 交易、逐步活动、许可及回执仅由内存 UI_MOCK 样本驱动，来源标签始终可见。保留手写确认，模拟签名不访问插件或后端。刷新重置，退出返回真实模式；模拟记录不写入真实历史、证据索引或发布队列。生产构建不开放该入口。

新增 2 条浏览器验证通过：无后端／无真实钱包完整体验、数据隔离与退出，以及手机从账户验收页进入体验。钱包共 17 条用例完成验证；一次磁盘空间不足导致的刷新检查失败已使用内存临时目录复跑通过。
